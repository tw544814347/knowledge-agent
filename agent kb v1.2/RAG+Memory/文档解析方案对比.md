# 文档解析方案对比

> **Page ID**: 2749044555
> **URL**: https://confluence.shopee.io/pages/viewpage.action?pageId=2749044555

开源 RAG 框架中的文档解析比较
-----------------

| Framework | Document Parsing Tooling | Supported Formats | Structured Parsing Capabilities | Comments |
| --- | --- | --- | --- | --- |
| LangChain | Unstructured, PyMuPDF, pdfminer.six, docx2txt, BeautifulSoup 等 | PDF, DOCX, HTML, TXT, Markdown, PPTX 等 | 可集成 Unstructured.io 进行段落级、元素级拆解 | 解析方式高度模块化，允许用户自定义文档加载器与分块逻辑。 |
| LlamaIndex (GPT Index) | Unstructured, PDFPlumber, PyMuPDF, HTMLReader, NotionLoader, WebPageReader 等 | PDF, DOCX, HTML, Markdown, Notion, Website 等 | 部分 Loader 提供块结构化（如 NotionLoader 可保留页面结构） | 通过 Document 对象封装元数据与段落，支持灵活文档分块策略（node parser）。 |
| Haystack (deepset) | PDFToTextConverter, PreProcessor, FileConverter, UnstructuredConverter 等 | PDF, DOCX, HTML, JSON, CSV 等 | 提供段落级分割、句子分割、表格处理等能力 | 集成 Unstructured 并配合 PreProcessor 提供自定义分块规则（窗口滑动、重叠等）。 |
| RAGatouille | 主要依赖外部工具（如 Unstructured）+ LangChain/LlamaIndex 的预处理能力 | 依赖集成框架支持的格式 | 无内建解析，仅聚焦于 RAG 管道 | 强调轻量、灵活组合，文档解析依赖于集成方。 |
| EmbedChain | 内建支持 PDF、网页抓取等；底层使用 pdfminer.six, BeautifulSoup, Unstructured 等 | PDF, HTML, Web URL, TXT | 有限结构化，主打快速构建与部署 | 适合轻量级场景，复杂文档需扩展或自定义。 |
| Semantic Kernel | 需用户接入第三方工具，如 Unstructured, Tika, LangChain 等 | 取决于外部工具集成 | 不提供原生文档结构解析能力 | 微软主导，文档预处理环节需用户自定义实现。 |
| PrivateGPT / GPT4All | 基于 LangChain 的 Document Loaders（如 DirectoryLoader, PyMuPDFLoader, UnstructuredPDFLoader） | PDF, TXT, DOCX 等 | 继承 LangChain 的分块能力 | 强调本地化部署，文档解析与分块全由 LangChain 提供。 |

技术方案对比总结
--------

* **Unstructured**: 几乎成为各大框架解析 PDF/DOCX/HTML 的事实标准，支持图文混排、分段识别、元素分类（标题、表格、列表等）。
* **自定义分块**: LlamaIndex 与 Haystack 提供强大的分块逻辑（如滑窗分块、重叠策略），适合上下文敏感的检索。
* **多格式适配**: LangChain 和 Haystack 的文档加载器最丰富，适合企业多样化文档来源。
* **结构保持能力**: LlamaIndex 在某些 loader（如 Notion、HTML）上保留结构信息较好，适合需要上下文保持的场景。
* **轻量场景**: EmbedChain 与 RAGatouille 更适合初学者或轻量级项目，但需要开发者对文档结构更主动地进行管理。
