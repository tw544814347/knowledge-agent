一、背景
----

AI 领域在沉寂一段时间后，每次技术革新会带来一波热潮，尤其是 GPT 横空出世后

### 1.算法发展

#### a.seq2seq

这是前期最典型的算法，定义如下：

概述版：使用 Encoder + Decoder 的组合，根据用户的输入使用 Encoder 生成向量，再根据向量生成结果

典型代表：语言翻译和文本摘要

优点：相对机器学习模型更加灵活，在文本生成领域表现良好，同时具备一定的上下文关联和理解能力

缺点：容易丢失上下文信息，在长序列中可能无法有效的捕获到远距离的依赖关系，并常用 LSTM 来改进 RNN 梯度消失问题

GPT 定义trueSeq2Seq（Sequence-to-Sequence）模型是一种用于处理序列数据的深度学习架构，特别适用于输入和输出都是序列的任务。它最初由 Google 在 2014 年提出，广泛应用于自然语言处理（NLP）领域。
1.主要组成部分
编码器（Encoder）：将输入序列编码为一个固定长度的上下文向量。
解码器（Decoder）：根据上下文向量生成输出序列。
2.优点
灵活性：可以处理不同长度的输入和输出序列。
强大的表示能力：通过使用循环神经网络（RNN）或长短期记忆网络（LSTM）等，能够捕捉序列中的长期依赖关系。
适用于多种任务：可以用于翻译、文本摘要、对话生成等多种应用。
3.缺点
训练时间长：由于模型的复杂性，训练时间可能较长。
固定上下文向量：传统的 Seq2Seq 模型使用固定长度的上下文向量，可能导致信息丢失，尤其在长序列中。
生成质量问题：在解码过程中，可能会出现重复或无关的输出。
4.典型应用
机器翻译：将一种语言的句子翻译成另一种语言（如英法翻译）。
文本摘要：从长文档中提取重要信息，生成简洁的摘要。
对话生成：生成与用户输入相应的自然语言回复。
图像描述生成：根据图像生成相应的描述文本。
5.进阶发展
Seq2Seq 模型的局限性促使了许多改进，如引入注意力机制（Attention Mechanism），进一步提高了模型在处理长序列时的性能。近年来，Transformer 模型的出现也在 Seq2Seq 任务中取得了显著的效果。

#### b.transformer

截止 202408 依然主流的算法，由 google 提出

* 引出 BERT 等大型预训练模型，极大的提高 NLP 任务的表现力，开启预训练模型 + 精调的时代
* 诞生 GPT3 等大型文本问答模型，具备归纳推理能力，百花齐放

概述版：同样使用 Encoder + Decoder 的组合，但引入 attention 机制来捕获输入序列中元素之间的关系

典型代表：文本理解和生成、问答系统如 GPT

优点：并行处理，多头注意力机制，能够捕获长距离依赖

缺点：模型大训练长、运行所需资源高

GPT 定义trueTransformer 是什么
Transformer 是一种基于注意力机制的神经网络架构，专门用于处理序列数据。它由两个主要部分组成：编码器（Encoder）和解码器（Decoder），每个部分由多个层堆叠而成。Transformer 通过自注意力机制来捕捉输入序列中元素之间的关系，而不依赖于传统的递归神经网络（RNN）。
优点
1.并行处理：Transformer 能够同时处理整个输入序列，这大大提高了训练速度。
2.长距离依赖：自注意力机制允许模型有效捕捉远距离词之间的关系，克服了 RNN 在长序列中的梯度消失问题。
3.灵活性和可扩展性：Transformer 的结构易于扩展，可以适应不同的任务和数据集。
4.多头注意力：通过多个注意力头，模型能够学习到不同的上下文信息，从而增强表示能力。
5.强大的性能：在许多自然语言处理任务中，Transformer 通常表现优于传统模型，如 RNN 和 LSTM。
缺点
1.计算资源需求高：Transformer 模型通常需要大量的计算资源和内存，尤其是在处理长序列时。
2.训练时间长：尽管支持并行处理，但大规模模型的训练仍然需要较长时间。
3.模型大小：Transformer 模型通常较大，可能导致在资源有限的设备上运行困难。
4.对数据量的依赖：Transformer 通常需要大量的训练数据来发挥其优势，数据不足时性能可能下降。
典型应用
1.机器翻译：Transformer 在机器翻译任务中表现出色，如 Google 的翻译系统。
2.文本生成：用于生成自然语言文本，如 OpenAI 的 GPT 系列模型。
3.文本摘要：自动生成文章摘要，提取关键信息。
4.问答系统：用于构建问答系统，理解问题并生成答案。
5.情感分析：在情感分析任务中，Transformer 可以有效捕捉文本中的情感信息。
6.图像处理：变种的 Transformer 结构（如 Vision Transformer）被应用于图像分类和目标检测等任务。
总结
Transformer 是一种强大的模型架构，具有并行处理、长距离依赖捕捉和灵活性等优点，广泛应用于自然语言处理和其他领域。然而，它也面临计算资源需求高和对数据量依赖等挑战。

### 2.应用发展

整体应用的发展链路为

* 机器语言翻译
* 文本摘要生成(seq2seq)
* 长文本理解(transformer)
* 大型语言预训练模型(LLM)
* 结合知识库，衍生出 GPT3 文本问答系统
* 结合处理图片视频等多种媒介的能力，衍生出 GPT4 多模态的大模型系统

但大模型作为生成式模型也有缺点[4]，如：

* 幻觉：生成无关的内容
* 结果并不总是真实：如了解买火车票的行为但不能执行购买操作
* 对时事一无所知
* 难以应对复杂计算推理
* 训练模型昂贵等等

因此为了解决这些问题，吴恩达也提出未来人工智能发展的四大设计[5]：

* 反思：LLM 检查自己的工作，并提出改进的方法，即思考
* 工具使用：LLM 利用Web搜索、代码执行或任何其他功能的工具，来帮助自己收集信息、采取行动或处理数据，即执行
* 规划：LLM 提出并执行实现目标的多步骤计划（比如一篇论文，首先写大纲，然后搜索和研究各部分内容，再写草稿），即任务分解
* 多智能体协作：多个AI agent协同工作，分工任务，讨论和辩论想法，提出比单个智能体更好的解决方案

而截至 202408，这四大设计的应用也有所体现

* 反思：我们大多数人使用LLM通常是 zero-shot 模式，即模型根据提示逐个输出token，没有返回修改的机会，但可以通过反复的提供  促使模型反思来修正结果，这正是当前 GPT 文本问答的设计，正是吴恩达所说，大模型具备“反思”
* 工具使用：LLM 识别并判断使用哪些工具，通过使用工具来完成任务，目前大部分落地场景属于这个阶段
* 规划：即 planning 阶段，懂得任务拆解和规划任务执行，目前也有许多的论文详述如何让 agent 具备 planning 能力[9]，但都有致命的问题：当复杂任务过程太长，错误会积累并导致 LLM 出现幻觉。工业界常见有百度千帆、阿里、讯飞等都在做 Agent 平台[7]
* 多智能体协作：目前市面上也有的框架如 MetaGPT、AgentVerse、Agents 等等[10]，multi-agent框架的核心还是在 agent 之间的交互与状态的转移。而 LLM 对工具的调用往往只是作为其中一个子模块，且大部分 agent 都只调用单个 tool。因此，在 multi-agent 的场景中，使用多个单 tool 的 agent 还是一个多 tool 的 agent，也是一个值得考虑的问题

### 3.目标

结合 LLM 的发展，吴恩达也提出，低阶大模型 + 工具 + 智能体工作流的效果，实际效果要比高阶模型更好，GPT3.5 + tools > GPT 4.0（截止 202408 大模型工业级落地仍处于该阶段）

这也得到了业界的验证：Agent 方案论文数量已经超过了底层 LLM 调用，某种程度，Agent 工程已经和底层 LLM 并驾齐驱的重要技术。LLM 实际场景应用落地同样和训练模型一样重要，我们不必干等一个全面无敌的 LLM 模型出现，低阶 LLM 一样受用

而具备更强能力的如：具备 planning 能力的 agent 存在幻觉问题，muti-agent 对我们的实际企业级落地而言，成本昂贵

因此有了 LLM 结合 tools 的使用，而这正是我们想要的、我们要做的，也是目前阶段结合大模型效益最高的，借用 LLM 的理解能力和逻辑推理能力，再加上我们贴合业务侧的 tools，用低成本让 GPT 在特定领域表现更好：

* 幻觉可控，可以将每个步骤单独一次 LLM 调用，避免链路过长导致的幻觉问题
* 准确率可控，通过流程编排(workflow)，每个步骤都有严格的错误率控制才能继续流程

主要实现方向为几点

* 让模型操作更加真实：即定制 tools，提供工具让 LLM 使用，具备如执行购买车票操作等解决真实问题的能力
* 让模型理解如何执行任务：即定制 prompt，约束 LLM 执行任务的步骤，在如 xxx 等提示下使用 xxx 工具，注意这里是由人工来实现了 planning，人工拆解了任务的执行步骤
* 更加贴合业务：即使用 RAG 技术，结合内部知识库，解决模型对训练集以外一无所知的缺点

二、Agent
-------

### 1.What

#### a.Agent

概述版：即根据外部输入后，能够处理数据并自主决策的系统

不同于传统的人工智能， AI Agent 具备通过独立思考、调用工具去逐步完成给定目标的能力。比如，告诉 AI Agent 帮忙下单一份外卖，它就可以直接调用 APP 选择外卖，再调用支付程序下单支付，无需人类去指定每一步的操作，目前国内也有非常多的实际落地场景，如 kimi、百度文心[11]

AI Agent 和大模型的区别在于：

* 大模型与人类之间的交互是基于 prompt 实现的，用户 prompt 是否清晰明确会影响大模型回答的效果，例如 ChatGPT 和这些 Copilot 都需要明确任务才能得到有用的回答。
* AI Agent 的工作仅需给定一个目标，它就能够针对目标独立思考并做出行动，它会根据给定任务详细拆解出每一步的计划步骤，依靠来自外界的反馈和自主思考，自己给自己创建 prompt，来实现目标。如果说 Copilot 是 “副驾驶”，那么 Agent 则可以算得上一个初级的 “主驾驶”。

GPT 定义true在大模型领域中，agent 通常指的是一种智能体，它能够在特定环境中自主执行任务并作出决策。以下是对 agent 的理解，包括其原理、特点和应用示例。
1. 理解 Agent
定义：在大模型和人工智能领域，agent 是一种能够感知环境、处理信息并采取行动以实现特定目标的系统。它可以是基于规则的，也可以是通过机器学习训练的。
2. 原理
感知：agent 通过传感器（如数据输入）获取环境信息。
决策：使用算法（如强化学习、深度学习等）对感知到的信息进行处理，生成决策。
行动：根据决策采取行动，影响环境并获得反馈。
3. 特点
自主性：能够在没有人类干预的情况下进行决策。
适应性：根据环境变化和反馈不断调整行为。
交互性：能够与其他 agent 或环境进行互动，形成复杂的行为模式。
4. 应用示例
1. 游戏 AI
例子：在视频游戏中，NPC（非玩家角色）可以作为 agent。它们能够根据玩家的行为做出反应，调整策略，提供更具挑战性的游戏体验。
2. 自动驾驶
例子：自动驾驶汽车中的智能体能够实时感知周围环境（如行人、其他车辆），并基于这些信息做出驾驶决策，如加速、减速或转向。
3. 聊天机器人
例子：聊天机器人可以作为一个 agent，理解用户的输入，并根据上下文生成自然语言响应，提供信息或解决问题。
4. 推荐系统
例子：在线购物平台的推荐系统使用 agent 根据用户的浏览和购买历史，实时调整推荐内容，提高用户体验和销售转化率。
总结
在大模型领域，agent 是一种重要的概念，体现了智能体的自主决策和适应能力。通过不断的学习和交互，agent 能够在复杂环境中有效地执行任务，广泛应用于游戏、自动驾驶、聊天机器人和推荐系统等多个领域。

Agent 目前是以大模型为核心的智能体，通过与用户对话的形式，来完成各种任务，它很像一个“人”。如果和人做类比

| 人类 | Agent |
| --- | --- |
| **大脑**: 决策什么时候要做什么 | **大模型**: 处理信息，决策要回答的问题或执行的动作 |
| **角色**: 人可以同时是不同的角色，每个角色都有自己的规则。例如，作为学生，必须上课，按时交作业 | **规则**: Agent充当特定角色，例如智能客服，只能回答相关问题和执行限定操作 |

| **技能**: 具有各种技能，如饥饿时使用“做饭”技能，可选择加热预制菜或自己做 | **技能**: Agent使用技能，分为插件（即插即用）和Flow（提前编排工作流） |

#### b.Workflow

LLM 和 Agent 诞生后，workflow 也分为传统和智能两派，分别定义如下：

GPT 定义-传统工作流true传统工作流
定义
传统工作流通常是指一系列预定义的、线性的步骤，通常由固定的规则和流程组成。这些步骤通常在一个中心化的系统中执行，强调任务的顺序和依赖关系。
场景
企业流程管理：如审批流程、订单处理、财务报表生成等。
制造业：生产线上的任务调度和资源分配。
文档处理：文件审核、签署和存档。
优点
简单易懂：结构清晰，易于设计和实现。
稳定性：对于固定流程，表现稳定，易于维护。
可预测性：流程执行结果可预测，便于监控和管理。
缺点
灵活性差：难以应对动态变化和突发情况。
效率低下：在复杂场景中，固定流程可能导致瓶颈。
响应速度慢：需要手动干预来处理例外情况。GPT 定义-基于 Agent 的工作流true基于智能体的工作流
定义
基于智能体的工作流利用多个自主智能体协作，动态地处理任务。每个智能体可以根据环境变化和任务需求作出决策。
场景
智能交通系统：车辆和交通信号灯之间的动态协调。
分布式监控：多个传感器和监控设备的实时数据处理。
机器人协作：多个机器人共同完成复杂任务，如仓储和物流。
优点
灵活性高：能够自适应环境变化，处理动态和不确定的情况。
效率提升：多个智能体可以并行处理任务，提高整体效率。
自主性：每个智能体可以独立决策，减少对中央控制的依赖。
缺点
复杂性：设计和实现相对复杂，需要更多的技术支持。
调试难度：多智能体系统的行为可能难以预测，调试和维护复杂。
资源消耗：可能需要更多的计算和存储资源。
总结
传统工作流适合于结构明确、变化较少的场景，强调稳定性和可预测性，但在动态环境中表现不佳。
基于智能体的工作流则适合于复杂、动态和不确定的任务，强调灵活性和自主性，但需要较高的设计和维护成本。

#### c.RAG

概述版：根据外部输入(如用户输入的文本)，从外部知识库获取相似度高的结果向量后，交由大模型的整合生成结果的一种设计

核心部分：如何外部数据处理为向量、如何存储知识库、如何检索高相似度向量、如何生成结果

GPT 定义true在大模型领域中，RAG（Retrieval-Augmented Generation）指的是一种结合了信息检索和文本生成的模型架构。它通过检索相关信息来增强生成文本的能力，从而提高生成结果的准确性和相关性。
1. 理解 RAG
定义：RAG 模型结合了检索模型和生成模型，首先从外部知识库中检索相关文档，然后基于这些文档生成最终的文本输出。
2. 原理
检索阶段：RAG 模型首先接收查询（例如，用户问题），并通过检索模型（如 BM25 或 Dense Retrieval）从知识库中找到与查询相关的文档。
生成阶段：接下来，生成模型（如 Transformer）使用检索到的文档作为上下文，生成响应或回答。这一过程通常涉及对输入文本的编码和解码。
3. 特点
信息丰富性：通过检索外部知识，RAG 能够生成更加信息丰富和准确的回答。
动态性：可以根据实时检索到的信息生成内容，适应性强。
效率：在生成过程中，利用外部知识库可以减少模型的记忆负担，提高生成效率。
4. 应用示例
1. 问答系统
例子：在一个问答系统中，用户提出问题，RAG 模型首先检索相关文档（如维基百科条目），然后生成基于这些文档的答案。这种方式能够提供更准确和上下文相关的回答。
2. 聊天机器人
例子：聊天机器人使用 RAG 可以在对话中实时检索信息，以便回答用户的具体问题，比如最新的新闻或特定领域的知识。
3. 内容生成
例子：在内容创作平台，RAG 可以帮助作者检索相关资料，然后生成高质量的文章或报告，确保内容的准确性和深度。
4. 法律文档分析
例子：在法律领域，RAG 可以用于检索相关案例和法律条款，帮助律师快速生成法律意见书或合同文本。
总结
RAG（Retrieval-Augmented Generation）通过结合信息检索和文本生成的优点，提供了一种高效且准确的文本生成方法。它在问答系统、聊天机器人、内容生成和法律文档分析等多个领域展现了广泛的应用潜力。

RAG 设计常与内部知识库结合，让 LLM 更加贴合业务

* 将用户意图 encode 为向量
* 在内部知识库中进行检索
* 将多个检索结果一同交给 LLM 进行归纳总结

### 2.Why

与传统的基于规则(rule-based)的系统相比

| 特征/方面 | 基于智能体的系统（Agent-based） | 基于规则的系统（Rule-based） |
| --- | --- | --- |
| **定义** | 由多个自治的智能体组成，能够感知环境并作出决策。 | 通过预设的规则库来处理信息和作出决策。 |
| **组件** | 智能体（Agent） | 规则（Rules） |
| **决策过程** | 分布式，每个智能体独立作出决策。 | 集中式，基于规则匹配结果作出决策。 |
| **灵活性** | 高，能够适应环境变化和新情况。 | 低，受限于预设的规则。 |
| **可扩展性** | 高，易于添加或修改智能体。 | 中等，添加新规则可能影响现有逻辑。 |
| **复杂性管理** | 通过智能体之间的交互来管理复杂性。 | 通过规则的复杂性来管理复杂性。 |
| **使用场景** | - 需要高度自治和适应性的系统  - 动态和开放的环境  - 需要协同工作的系统 | - 规则明确且相对固定的场景  - 决策过程可以严格用规则描述  - 需要快速响应确定性结果的系统 |
| **优点** | - 能够处理不确定性和复杂性  - 易于实现模块化和重用性  - 智能体可以自主学习 | - 易于理解和验证  - 规则库明确，便于调试  - 决策过程透明 |
| **缺点** | - 设计和实现可能复杂  - 难以预测所有智能体行为  - 可能存在通信和协调开销 | - 对新情况适应性差  - 规则冲突可能难以解决  - 规则库可能迅速膨胀导致复杂性增加 |

针对 C 端变动的如图像识别等需求，用 Agent 的优势远大于 Rule-based

### 2.How

常见的 agent 设计如下，对于实际落地场景

* 底层 LLM 择优即可，无需自己训练
* 我们更加关注 prompt 的提供、tools 的注册、与 LLM 之间的调用等，由 LLM 自主归纳整理并借用 tools 辅助完成 action 操作

![91dea70c3ba540d884467a8f3567d43d~tplv-tlddhu82om-image.image](https://p6-volc-community-sign.byteimg.com/tos-cn-i-tlddhu82om/91dea70c3ba540d884467a8f3567d43d~tplv-tlddhu82om-image.image?=&rk3s=8031ce6d&x-expires=1724911382&x-signature=GcjmCdQ56%2Bs%2BkAYIrflqbTRvMSg%3D)

Agent 在给定 Prompt 下，在 Prompt 中指定工作流程，LLM 理解并调用多个 tools 形成工具链并执行，将用户的输出转化为结果输出

整体流程为：

* 用户指定 Prompt，在 Prompt 指定流程，形成 workflow
* 在需要匹配内部数据的情况下，使用 RAG 设计让 LLM 更加贴合业务：通过 prefill 理解用户意图形成向量，并通过知识库搜索获得多个意图向量，由 LLM 进行归纳汇总
* LLM 识别意图向量，结合 Prompt，调用不同的 tools 完成工作
* 将结果返回用户

M、术语扫盲
------

* **Prefill** 指的是在生成文本之前，模型对用户输入进行预处理的阶段。这一阶段主要负责将用户的查询或输入转换为模型可以理解的格式，并进行必要的计算，以便为后续的文本生成做好准备。
* **Time To First Token (TTFT)** 、是指从用户输入到模型生成第一个 token 所需的时间。这个指标对于用户体验非常重要，因为它直接影响用户在交互过程中的感知延迟。
* **MFU (Maximal Forward Utilization)** 是指在处理多个请求时，模型资源的最大化利用程度。提升 MFU 意味着通过有效的批处理和资源管理来提高 GPU 的计算效率，从而减少资源浪费。
* **Time Between Tokens (TBT)** 、是指模型生成连续两个输出 token 之间的时间间隔。这个指标影响流式输出的流畅性和速度，尤其在 autoregression（自回归）生成过程中，优化 TBT 可以提升用户体验。
* **Decode** 指的是模型生成文本的阶段
* **Prompt** 是用户提供给语言模型的文本、问题、指令、上下文或任何其他形式的输入，旨在激发模型生成相关的输出。Prompt
