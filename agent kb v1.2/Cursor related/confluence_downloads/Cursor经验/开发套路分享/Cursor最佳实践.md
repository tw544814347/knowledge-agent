**Cursor 最佳实践**

我正在使用 Cursor，所以想先了解一下使用它的最佳实践。这是为了确保在我进行项目工作时，不会被复杂性所困扰。

**核心实践指南：**

**1. 项目启动前详细规划**

在完全投入项目之前，先向 Claude 询问详细的 markdown 计划（让它提出澄清问题，然后批评自己的计划并重新生成）。将其添加到 [instructions.md](http://instructions.md) 中（这样你可以经常要求 Cursor 参考它）

如果我不知道想要创建什么，那么我会让它为另一个负责编码的 AI 提供指令。然后我将所有内容粘贴到 Cursor composer agent 中

**2. 增加规划层次**

基本上 ChatGPT 增加了另一层规划，减少了遇到问题的机会

**3. 遇到问题时重新开始**

在一个项目上，Cursor 遇到了一些问题，无论如何都无法解决。我浪费了几个小时陷入循环。然后我从头开始，但这次我让 ChatGPT 为另一个开发者编写清晰的指令来处理代码。效果非常好

**4. 使用 Cursorules 设定广泛规则**

使用 cursorules（它们始终在 AI 上下文中）告知广泛的规则。参见 **https://cursor.directory/**

例如：先写测试，然后写代码，接着运行测试并更新代码直到测试通过

**5. 让 AI 以增量方式获取代码**

让 AI 以小块的编辑+测试循环增量式编写代码：

* 定义一个小任务或功能增量
* 编写（或让 AI 编写）一个针对此增量失败的测试用例
* 指示 AI（通常在 Agent 模式下）编写/使测试通过
* 指示 AI 运行测试
* 如果测试失败，AI 分析失败原因并尝试修复代码，循环回到步骤 4
* 一旦测试通过，开发者审查更改

**6. 在提示中鼓励思维链**

当遇到问题时，让 Cursor 写一个报告，列出所有文件及其功能和遇到的问题。询问 Claude/ChatGPT 如何解决问题

**7. 使用 [gitingest.com](http://gitingest.com) 获取项目概览**

使用 **[gitingest.com](http://gitingest.com)** 将所有脚本配置或最新文件一页式地提供给 Claude（通过扩展），在单页面中提供给 ChatGPT 处理

**8. 使用参考开放编辑器快速添加到上下文**

使用 /Reference open editors 快速将它们添加到上下文中

**9. 参考最新文档**

使用参考开放文档来获取最新文档。MCP 用于参考最新文档

**10. 频繁使用版本控制**

频繁使用 Git 进行版本控制。不要有太多未提交的更改

**11. 保持上下文简短并适时重新开始**

通过明确添加**不再需要上下文的文件**来保持上下文简短，这样 AI 会更详细地处理

当上下文变长时开始新的对话

**12. 重新同步/索引代码**

频繁重新同步/索引代码

* 使用 .cursorignore 排除无关文件
* 使用 /Reference open editors 快速将编辑器添加到上下文中

**13. 使用记事本存储常用提示**

记事本是存储常用提示的好方法

**14. 可选：启用 YOLO 模式进行无限制测试**

启用 YOLO 模式以便使用无限制测试

* 任何类型的测试都被允许，如 vitest、npm test 或 test 等
* 基本的构建命令如 build、tsc 等也可以
* 创建文件和目录（如 touch、mkdir 等）也总是可以的

**15. 可选：在"AI 规则"中设置系统提示**

在 Cursor 设置的"AI 规则"中设置系统提示：

* 保持答案简洁直接
* 建议替代实现方案
* 避免不必要的解释
* 优先考虑技术细节而非泛泛建议
