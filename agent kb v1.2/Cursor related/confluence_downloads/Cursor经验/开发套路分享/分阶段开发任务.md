## 理解项目结构和流程

### 分析项目
请分析本项目的主要流程，包括但不限于核心模块、关键数据流、主要函数或类的职责划分，以及模块之间的依赖关系。
将分析结果以简洁、清晰的方式撰写为一份 arch.md 文件，内容应包括：
1. 系统架构概览：概括项目的整体结构和主要组成模块。
2. 流程说明：按主要业务流程梳理系统如何运作（如请求流程、数据处理流程等）。
3. 模块职责与关系图：明确各模块的职责，并展示它们之间的依赖或调用关系。
4. 设计动机与技术选型简述（如有明显技术取舍）。
5. 潜在的可扩展点与注意事项（供后续开发参考）。
要求：
* 内容聚焦于已有逻辑，不编造不存在的结构。
* 适合供后续开发者快速理解当前架构与设计意图。
* 用 Markdown 编写，结构清晰，配图（如 Mermaid）可以辅助理解流程。
将内容写入项目根目录下的 arch.md 文件中。
