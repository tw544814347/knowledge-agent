# 系统挑战

> **Page ID**: 2792987211
> **URL**: https://confluence.shopee.io/pages/viewpage.action?pageId=2792987211

| 挑战领域 | 清醒的现实 (The Sobering Reality) | 给决策者的关键问题 (Critical Questions for the Business) |
| --- | --- | --- |
| 技术与架构  (Technical & Architectural) | 1. “因材施教”的**复杂性代价**: 我们设计的专用处理流水线（为法律、PRD、数据表等）非常强大，但其开发、维护和治理成本远超单一的、通用的流水线。每增加一种文档类型，都意味着一套新的、需要长期维护的逻辑。  2. 智能的“计算税”: 深度元数据提取（如图片信息提取、图表结构化、用户故事影响分析）**依赖LLM模型和大量计算资源（消耗大量token）**。这笔“智能税”是持续性的运营成本，而非一次性投入。 | - 我们是否准备好投入一个专门的团队，来长期维护一个多元化、而非单一的解析引擎？  - 我们是否对高级分析功能（如每天处理数千份文档）的LLM服务成本有清晰的、可接受的预期？ |
| 知识与数据  (Knowledge & Data) | 3. “元数据税”与内容创作惯性: 要求文档创建者（如产品经理、数据工程师）在创作时就提供丰富的、结构化的元数据，是在挑战他们根深蒂固的工作习惯。这会带来额外的“元数据税”，极易遭到抵制或被敷衍了事。  4. “**隐性****知识**”的鸿沟: 公司最有价值的知识，往往存在于资深员工的大脑、Seatalk讨论串和会议纪要中，而非结构化的文档里。RAG系统无法读取这些“非正式”知识，导致其回答在关键时刻可能“在理，但不在情”。 | - 我们是否有决心和策略（如流程改革、工具集成）来改变研发人员的工作方式，而不只是寄希望于研发人员的非约束性的自觉？  - 我们如何管理团队的期望，让他们明白RAG是强大的副驾，而非全知的神？我们如何弥补“隐性知识”的鸿沟？ |
| 组织与人性  (Organizational & Human) | 5. “知识孤岛”与“所有权真空”: 知识的质量和准确性，其最终责任人必须是源头的知识所有者（如法务团队对条款负责）。如果将责任推给“RAG平台团队”，平台将沦为一个无人信任的“高质量垃圾桶”。  6. “首次信任”的脆弱性: 用户对AI的信任极度脆弱。如果在推广初期，系统给出了几个错误的、尤其是在高风险领域的答案，其声誉可能被永久摧毁，再难获得推广和采纳。 | - 我们是否已经明确了每个知识域的“所有者”？他们是否愿意并有资源来承担“确保RAG中相关知识准确无误”的责任？  - 我们的推广策略是什么？是全面铺开，还是先在容错率高、价值明显的场景（如辅助研发）进行试点，建立“口碑和信任”的护城河？ |
